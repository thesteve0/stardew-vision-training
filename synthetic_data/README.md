# Synthetic Data Generation

LLM-based synthetic data generation to augment real screenshots.

---

## Purpose

With only 15-20 real screenshots per screen type, we need to generate synthetic variations to create a sufficient training dataset (~150 examples per type).

**Strategy**: Use LLM (Claude/GPT-4) to generate plausible variations of OCR outputs and narrations based on real examples.

---

## Approach

1. **Collect 15-20 real screenshots** with ground truth annotations
2. **Extract patterns** from real annotations (narration templates, field variations)
3. **Generate synthetic variations**:
   - TV dialog: Different weather, fortune, cooking recipes
   - Caught fish: Different fish species, lengths, qualities
   - Pierre's shop: Different items, prices, quantities
4. **Create ChatML conversations** for each synthetic example
5. **Combine real + synthetic** for training dataset (~150 per screen type)

---

## Tools

### generate_variations.py

**Usage**:
```bash
python synthetic_data/generate_variations.py \
  --screen-type tv_dialog \
  --num-variations 100 \
  --output datasets/tv_dialog/conversations_synthetic.jsonl
```

**Process**:
1. Load real annotations from `datasets/{screen_type}/annotations.jsonl`
2. Extract narration templates and field patterns
3. Generate variations using LLM
4. Format as ChatML conversations
5. Save to output JSONL

**LLM provider**: Uses OpenAI API (compatible with Claude via Anthropic's API)

## Variation Types

### TV Dialog

**Real example**:
```json
{
  "tv_show": "weather_forecast",
  "dialog_text": "Welcome to KOZU 5... weather forecast for tomorrow..."
}
```

**Synthetic variations**:
- Different weather: sunny, rainy, stormy, snowy
- Different channels: KOZU 5, alternative names
- Different phrasing: "And now the forecast", "Tomorrow's weather", etc.

### Caught Fish

**Real example**:
```json
{
  "fish_name": "Rainbow Trout",
  "length": "23 in.",
  "quality": "normal"
}
```

**Synthetic variations**:
- Different fish species (from item_manifest.json)
- Different lengths: 10-50 inches
- Different qualities: normal, silver, gold, iridium

### Pierre's Shop

**Real example**:
```json
{
  "item_name": "Parsnip Seeds",
  "description": "Plant these in spring...",
  "price_per_unit": 20,
  "quantity": 5,
  "total_cost": 100
}
```

**Synthetic variations**:
- Different items (from item_manifest.json)
- Different quantities: 1-999
- Different prices (realistic ranges)

## Templates

Templates define narration structure for each screen type.

**Location**: `synthetic_data/templates/`

**Example** (`tv_dialog_template.txt`):
```
TV {tv_show}: {dialog_text}
```

**Variations** generated by LLM while preserving template structure.

---

## Quality Validation

After generating synthetic data:
1. **Manual review**: Inspect sample outputs for plausibility
2. **Format validation**: Ensure ChatML structure is correct
3. **Field validation**: Check OCR fields match expected schema
4. **Diversity check**: Ensure variations cover range of possibilities

---

## Output Format

Synthetic conversations saved as JSONL (same format as real):

```json
{
  "messages": [
    {"role": "user", "content": [{"type": "image", "image": "..."}, {"type": "text", "text": "What's on this screen?"}]},
    {"role": "assistant", "tool_calls": [{"function": {"name": "crop_tv_dialog", ...}}]},
    {"role": "tool", "name": "crop_tv_dialog", "content": "{...synthetic OCR...}"},
    {"role": "assistant", "tool_calls": [{"function": {"name": "text_to_speech", "arguments": "{\"text\": \"...synthetic narration...\"}"}}]}
  ],
  "metadata": {
    "synthetic": true,
    "source_image_id": "uuid-of-real-example",
    "variation_type": "weather_sunny"
  }
}
```

## Best Practices

1. **Use real examples as templates** — Don't generate from scratch
2. **Preserve domain knowledge** — Fish names from item_manifest.json, not invented
3. **Validate field relationships** — price_per_unit × quantity = total_cost
4. **Review quality** — Manually check 10-20 synthetic examples before training
5. **Balance variations** — Equal distribution across subtypes (weather, fortune, cooking, etc.)
